## 改善内容

| ID  | 対応                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | 通常作成・WebMCP経由の作成・練習用図の作成／削除で、一覧とバックアップ件数を一緒に更新する。同一QueryClient・20秒キャッシュでも作成直後から離脱保護が有効になる                                   |
| R2  | タブ固有の一時利用を他タブの永続マーカーより優先する。このタブで永続保存を選び直した時だけ一時マーカーを消す                                                                                      |
| R3  | 削除完了をBroadcastChannelとstorageイベントで全タブへ通知する。通知を受けると保存モード・ストアキャッシュ・クエリをクリアし、Reactの画面・フォームを作り直す。再読み込みの確認に依存しない        |
| R4  | 4秒を超えた削除は失敗扱いにせず「保留」と通知する。要求は完了まで待ち続け、同一タブの重複要求を共有する。保留中は再実行・キャンセル・書き出し操作を抑止し、遅れて成功した場合もR3の消去を実行する |
| R5  | 定義・既存データの読み取りと追加インポートを、同じIndexedDB readwriteトランザクションで実行する。中途失敗は全体がロールバックされ、別ストアインスタンスからの同時追加も取りこぼさない             |
| R6  | `kdf.name` がPBKDF2、`kdf.hash` がSHA-256であることを復号前に検証する。不正な宣言はBACKUP_INVALIDで拒否する。暗号形式・旧形式互換は維持する                                                       |
| R7  | 通常・図ごと・暗号化のすべての出力を、取り込みと同じスキーマ・件数上限と実際のUTF-8バイト数で検証する。読み戻せないファイルを保存成功として出力しない                                             |

R7は1ファイルの相関図1,000件・50MiBという既存の取り込み上限を維持している。1,001件以上の既存データを一括で分割保存する機能は追加していない。上限を超えた場合は明確なエラーと図ごとのJSON出力を案内し、元の図は変更しない。通常出力が上限内でも、暗号化後に超えた場合は出力を止める。

## 検証

- Vitest **52ファイル・406件成功**。ESLint、TypeScript、Prettier、production build成功。
- R1: 一時利用とIndexedDB退避の双方で、同じキャッシュのまま「0件→作成→即離脱」を検証。最後の図を削除した後の保護解除も確認。
- R2: 他タブの永続マーカー追加後も一時利用の警告・離脱保護を維持する回帰テスト。
- R3: 別タブの通知で古いフォームとクエリが消え、保存方法の選択に戻ることを検証。通知の重複排除と購読解除も確認。
- R4: 保留中に失敗扱いや部分消去をせず、後から成功した時だけ完了すること、重複要求が増えないことを検証。画面の保留表示と操作抑止も確認。
- R5: 最後の書き込み準備で失敗しても図・定義が変わらない回帰テスト。実IndexedDBでもQuotaExceededErrorを模した中途例外によるロールバックと、独立した2ストアからの同時追加を確認。
- R6: KDF方式・ハッシュ宣言の改ざん拒否と、既存の暗号往復・旧形式読み込みテスト。
- R7: 1,000件の全件出力は読み戻せる。1,001件の全件出力は明示的に拒否し、図ごとの出力は読み戻せる。縮小したサイズ上限を使い、通常・暗号化後・図ごとのサイズ超過も確認。

## 互換性と残る制約

- 新しい全タブ消去に対応していない旧版のタブは通知を受けられない。導入時は開いているアプリの全タブを一度更新する。共有端末では引き続き全タブを閉じて引き渡す。
- 旧版で一時利用から永続保存に変更したタブに一時マーカーが残っている場合、新版はプライバシー保護のため一時利用を優先する。必要ならこのタブで永続保存を選び直す。既存のIndexedDBは削除しない。
- beforeunloadはブラウザの強制終了等を防ぐ保証ではない。Service Worker自動更新による再読み込みの設計、およびOS保存ダイアログ・Firefox/Safariの確認範囲は、元の報告書に記載した制約が残る。
