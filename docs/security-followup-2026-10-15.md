# 残タスクの改善と追加検証

実施日: 2026-10-15 / 作業元: main `af32ff7`  
状態: ローカルの修正・検証を完了。GitHubへのコミット・pushと本番反映は未実施。

## 更新時の一時データ保全

- 更新方針をpromptに変更し、Workerの自動skipWaiting・clientsClaimを無効化した。起動・画面復帰・オンライン復帰時の更新確認は維持する。
- vite-plugin-pwaのonNeedReloadを明示的に処理し、別タブでWorkerが有効になっても、このタブは自動再読み込みしない。
- 更新バーにJSON書き出しと保存・書き出し済みの確認を設けた。更新操作前とJSON生成前には、エディターのタイトル・人物・同居情報等の保留中の保存を待つ。保存失敗では更新を開始しない。
- 保存方法が未選択の場合、更新バーのJSON操作からストアを初期化しない。有効化のタイムアウト・更新失敗・再読み込み取消後も操作を再試行できる。
- 他タブ更新後に古いエディター資材が取得できなくなっても、Reactツリー全体を落とさず、JSONに退避できる回復画面を表示する。

参考: [Vite PWAの更新通知](https://vite-pwa-org.netlify.app/frameworks/)、および導入済みvite-plugin-pwa 1.3.0のRegisterSWOptions・登録処理の実装を確認した。

### 実ブラウザでの更新試験

隔離オリジン `127.0.0.1:4221` に変更後のproduction buildを複製し、HTMLの検証用識別子だけをA→Bへ変えてService Workerを再生成した。観測コードは公開用distとは別に配置した。

1. AのWorker管理下で、タブAに架空の一時相関図、タブBに架空の永続相関図を作成。
2. 新版Bを配信するとwaitingになり、通知だけが表示された。タブAで「あとで」を選んでも一時相関図と離脱保護を保持。
3. タブBの更新バーからJSON出力を実行。退避確認をチェックし、明示的に更新すると、タブBだけが新版Bへ再読み込みされた。永続相関図の最新タイトルは保持。
4. タブAは版Aの画面と一時相関図のまま残った。controllerChangesは1、lastUnloadPreventedはtrueで、別タブの更新によりページが再読み込みされていないことを確認。

JSONはapplication/json・11,402バイトのBlobとダウンロード操作の開始、アプリ側の完了表示までを確認した。接続ブラウザのdownloadイベントは取得できず、標準Downloadsの既知のテストファイル名でも保存ファイルを確認できなかったため、**OSへの保存完了・保存場所の確認は未完了**。観測コードでFile System Access APIを外して通常ダウンロードへ退避した試験であり、ネイティブ保存ダイアログの実機確認ではない。単体テストでは保存先選択→編集のflush→JSON生成→書き込みの順序、取消・失敗を確認した。

`127.0.0.1:4222` ではService Worker登録を止め、エディターのJSだけ404にした。作成後に回復画面が表示され、beforeunloadは有効、JSON出力操作が可能で、一覧へ戻ると架空の図が保持されていた。回復画面から取得したJSONに図のタイトルが含まれることは回帰テストでも確認した。

## 存在しない資材の配信

- 軽量の配信ルーターを `src/worker.ts` に追加。ASSETS bindingとnot_found_handling:noneを使い、実在資材はCloudflareの静的配信を優先する。run_worker_firstを設定せず、正規のJS取得ごとにWorkerを実行しない。
- 存在しない `/assets/` のGET・HEADは404、text/plain、Cache-Control:no-storeとし、SPAのHTMLや一年のimmutableキャッシュを返さない。その他のメソッドは405・no-store。
- 存在しない画面URLのGET・HEADだけはルートHTMLへ渡す。既存のReact Routerによる画面遷移を維持する。Service Worker側もassetsをnavigation fallbackから除外した。
- セキュリティヘッダを維持し、HTMLのETag・Content-Encoding等をエラー応答へコピーしない。Cloudflareローカル実行で8ケースを確認し、Wranglerのdeploy dry-runも成功した。実在資材優先の挙動は [Cloudflare公式資料](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/) を参照した。

ローカル結果: 画面の深いURL・ヘルプはHTML 200、正規JSはJavaScript 200・immutable、欠落JSは通常取得・navigationとも404・no-store、欠落CSSのHEADも404・no-store、資材へのPOSTは405・no-store、sw.jsは200・no-cache。記録は [配信試験](security-evidence/followup-2026-10-15/worker-routing.json)。本番への適用と本番での再確認はまだ行っていない。

## 履歴復帰と検証環境

- 永続利用のエディターから同一オリジンの別文書へ移動し、別タブで架空データを全削除してから履歴で戻った。古い図は表示されず、保存方法選択へ戻った。pageshow.persistedはfalseで、BFCacheからの復元ではなく再読み込みだった。
- 接続されている実ブラウザはBrave（Chromium系）の既存プロファイルのみ。Firefox/Safari・本番用の独立プロファイル・ネイティブアプリの操作面は利用できない。
- 強制的なタブ凍結、OSの休止・終了、ネイティブ保存ダイアログの操作は実施できていない。これらを履歴復帰やjsdomの模擬試験だけで確認済みとはしていない。
- 本番に既存データがあるプロファイルは操作せず、今回の入力・削除・更新は新規ローカルオリジンの架空データに限定した。

## 検証結果

- Vitest **59ファイル・428件成功**。ESLint、TypeScript、Prettier、production build成功。
- 追加の回帰テストは、更新待機・他タブによる有効化、保存失敗時の中止、保存待機とタイムアウト、未選択時のストア保護、退避確認・取消・再試行、資材失敗時のデータ回復、配信ヘッダ・ステータスを検査する。

- Wranglerローカル実行で生成される.wranglerをESLintの対象外にした。生成コードの誤検出によるlint失敗を防ぐためで、アプリコードの検査は維持した。
- 検証補助のHTML・JS・配信切り替えはリポジトリ外に置き、公開用distには含めていない。ヘルプと配信手順も新しい挙動へ更新した。
