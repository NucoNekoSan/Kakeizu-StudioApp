## P1: 削除前の保存処理を失効させる

- メモリ・IndexedDBストアに寿命を持たせ、削除やモード変更前に取得した参照は `STORAGE_RESET`（409）で拒否する。同じタブの削除保留中には新規の既定API呼び出しも拒否する。
- IndexedDBストアは取得時の最初のawaitより前にopenを要求し、他タブからの削除でversionchangeを受けられるようにした。versionchange・異常close後の古いストアは再openしない。削除後の明示的な新規ストア取得は許可する。
- 取得済みAPIの復号後の書き込み、キューで待っていた追加、merge・replaceの双方が古いストアへ書き込めない回帰テストを追加した。削除失敗・保留、ストア再取得、既存の破損データ回復も検証した。
- 実IndexedDBで元の再現コードを再実行し、取り込みはSTORAGE_RESET、削除後の図は0件となった。さらに別々のタブで、片方の復号中にもう片方から全削除しても同じ結果となることを確認した。

## P2: タブ間で保存API全体を直列化する

- `DocumentStore` に任意の `runExclusive` を追加。永続ストアでは同一オリジンで共通のWeb Lockを取得し、APIの読み取りから書き込み完了までをまとめて直列化する。メモリストアは従来の同一ストア単位キューを使用する。
- ノードだけでなく、タイトル・配置・同居情報・定義・取り込み・出力も同じ境界に含め、古い読み取りに基づく全体上書きを防ぐ。同じ項目に意図して後から送った変更は要求の実行順で適用する。編集画面間のリアルタイム同期やリビジョン競合UIは追加していない。
- Web Locksが存在しない環境では永続ストアを開かず、既存のメモリ退避・常時警告を使う。ロック取得要求自体が拒否された場合は操作エラーにし、無保護の書き込みを続けない。
- 独立したストアを使う回帰テストと実IndexedDB試験で、同時追加した両ノードの保持、タイトル変更と人物追加の保持、失敗後のキュー継続を確認。別タブからの同時追加も両方保持された。mergeの原子的ロールバックも維持した。

Web Locksの同一オリジン内の排他制御は [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) と [W3C仕様](https://www.w3.org/TR/web-locks/) を確認して採用した。

## P3: 離脱保護を画面コンポーネントから分離する

- beforeunloadの登録を表示用バナーから `TemporaryDataProtection` へ移した。保存方法の選択後、ルートのSuspenseより外側で保持し、初回エディター読み込み中もハンドラーを維持する。
- 保存モード・メモリ退避の変化をuseSyncExternalStoreで購読する。未選択状態では保護用のクエリからストアを初期化しない。空の一時利用では警告ダイアログを要求せず、図の作成後は保護し、最後の図の削除後・アンマウント後には解除する。
- 実際のAppでlazyエディターのimportを未解決のままにし、一時利用と永続保存からのメモリ退避の双方で保護が有効な回帰テストを追加した。
- production buildのエディターチャンクを8秒遅らせた実ブラウザで、「エディターを読み込んでいます」の間も `lastUnloadPrevented: true` を確認した。Service Workerの登録を止めた初回読み込み条件で、アプリの保護処理は改変していない。

## 公開時の注意と残る制約

- 新しい排他制御・参照失効に未対応の旧版タブをすべて更新する。旧版が混在した状態での競合防止を保証する変更ではない。
- ロックを保持したタブが長時間停止すると、他タブの操作は待たされ得る。そのタブを閉じるとブラウザがロックを解放する。無理なロックの横取りはしていない。
- 保存形式・暗号形式は変更していない。既存のバックアップはそのまま利用できる。
- 前回確認した旧版Service Worker更新時の一時データ消失、Firefox/Safari、OS保存ダイアログ、強制終了等の制約は別途残る。今回のP3修正だけで更新時の一時データ保全を全面的に解決したとはしていない。
